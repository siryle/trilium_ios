# Trilium Pocket

适合 iPhone 的独立 Trilium 客户端，使用 SwiftUI、WebKit 和 Trilium ETAPI。支持 iOS 17 及以上，无第三方依赖。构建、测试和未签名 IPA 发布全部使用 GitHub Actions。

## 已实现的功能

| 入口 | 使用方式 |
| --- | --- |
| 笔记 | 按服务端 branch 顺序浏览目录，显示克隆笔记的前缀；点击笔记阅读，点击文件夹进入子目录，下拉刷新，右上角新建。 |
| 查看与编辑 | 文本笔记支持适配手机的 HTML 阅读、内嵌 Trilium 图片、笔记链接、富文本格式工具栏；代码和 Markdown 可编辑。复杂 HTML 使用源码编辑以保留原结构。修改保存在本机草稿，重启可恢复。 |
| 今天 | 主动打开或创建服务端日期笔记，遵循服务端日历模板；快速记录创建当天的子笔记，保留已有日记正文。 |
| 搜索 | 搜索标题及正文，支持 Trilium 查询语法；选择目录范围，输入延迟 350 ms 并取消过期请求，最多显示 100 条。 |
| AI | OpenAI 兼容接口的流式聊天，可停止、重试、选择附加笔记上下文；本机保存当前会话草稿，可保存到选定目录或当日日记下面，后续保存更新同一笔记。 |

## 连接服务

1. 在 Trilium 设置的 ETAPI 页面创建专用令牌。
2. 打开客户端「设置」，输入基础地址，例如 `https://notes.example.com` 或 `https://example.com/trilium`，无需附加 `/etapi`。
3. 输入令牌，点击「测试连接」，成功后保存。
4. 如需 AI，填写模型服务的 API 基础地址，例如 `https://api.openai.com/v1`、模型 ID 和自己的 API Key。无需使用 AI 的用户可保留默认值。

HTTPS 为默认要求；自托管 HTTP/IP 地址必须在设置中明确打开「允许 HTTP 连接」。HTTP 会明文传输令牌和正文。客户端保留系统 TLS 证书验证，拒绝携带凭据的重定向，请填写最终服务地址。

ETAPI 令牌和模型 API Key 分开存入 Keychain，不写入配置文件或对话笔记。草稿与当前对话保存在应用沙盒，使用 iOS 数据保护并排除云备份；按服务端分开保存。AI 对话还按服务商和模型分开。开始「新对话」会清除本机当前对话，服务端保存的笔记仍保留。

## AI 的工作方式

Trilium 的公开 ETAPI 不包含 AI 对话生成接口，服务端浏览器的 `/api/llm-chat/stream` 需要会话及 CSRF 认证。客户端通过独立配置的 OpenAI 兼容 `/chat/completions` 服务生成回复，再通过 ETAPI 保存普通 HTML 文本笔记。因此无需复用浏览器登录，也不会读取服务端私有 AI 密钥。

在笔记菜单中选择「附加到 AI 对话」，下一条消息可通过开关附带该笔记正文。界面显示模型服务域名，已附带的上下文会随后续对话历史继续发送。不会自动上传整个知识库。单个附带笔记上限 200 KB，总请求正文历史上限 400 KB，具体模型的上下文窗口还可能更小。

聊天回复支持文字、Markdown 显示和选择复制；停止、失败或超出限制的回复会保留并标记，不作为后续 assistant 历史。保存时将消息安全转义为 HTML，并记录模型、时间和上下文来源。支持重试保存、修改标题、目录选择及另存副本。保存为普通文本笔记，当前版本不会将其导入为 Trilium 原生 `llmChat` 类型或在客户端重新打开旧的服务端聊天继续生成。

## 数据保存与兼容范围

- 原生编辑支持未受保护的 `text`、`code` 笔记；图片可阅读，文件附件提示在 Trilium 中查看，其他类型按只读源码展示。
- HTML 阅读使用独立的非持久 WebKit 存储，禁用服务端脚本和外部资源。PNG/JPEG/GIF/WebP 内嵌 Trilium 图片通过 ETAPI 加载；外部图片、SVG、视频和交互式嵌入暂不显示。复杂 HTML 编辑保留源码，不会因修改标题而替换为经过净化的预览。
- 同一服务端同一笔记在各标签页共享编辑状态。每次保存先比较服务端标题和正文；已发生的修改会触发冲突提示，保留草稿并允许保存副本。
- **ETAPI 没有原子的条件更新接口，标题与正文也是两次请求。** 检查之后、写入之前仍存在其他客户端同时修改的时间窗口。客户端按每次成功写入更新本地基线，以便部分失败后重试；重要内容可主动另存副本。不能将本客户端视为提供严格的并发版本控制。
- 当前版本要求网络连接读取服务端笔记；本机草稿不是整个知识库的离线缓存。目录在进入时按需读取，并限制请求并发。

接口契约核对基于官方 TriliumNext v0.106.0 和当前 main，见 [API 说明](docs/API.md)。

## 构建和下载 IPA

参见 [GitHub Actions 发布说明](docs/RELEASING.md)。

- 推送 `main` 或创建 PR：执行模拟器 XCTest 及未签名 iPhone 归档验证。
- 推送 `v1.0.0` 一类版本标签，或手动触发并选择已存在的版本标签：测试后生成 `TriliumPocket-<tag>-unsigned.ipa`，上传到 GitHub Releases，附 SHA-256 校验和及源提交 ID。
- 不需要 Apple 证书、描述文件或签名 Secrets，也不执行任何第三方依赖安装。
- 未签名 IPA 需要使用你选择的签名工具和有效的 Apple 签名后，才能安装到普通 iPhone。

目前工作区的 `origin` 为 Gitea。GitHub Actions 需要 GitHub 仓库承载这些代码；本地提交不会自行推送或自动运行工作流。

## 用户验收

浏览器行为和真机体验由用户检查。首次 Actions 运行确认编译与 XCTest 后，建议在独立测试目录进行以下验证：

1. 配置直连和反向代理子路径地址，测试成功及错误令牌；确认未授权 HTTP 被拒绝。
2. 浏览多级目录及具有多个父目录的克隆笔记，验证排序、前缀和笔记内链接。
3. 阅读包含列表、表格、图片的文本笔记；编辑格式、修改标题、保存，并在服务端检查。退出后重新打开未保存草稿。
4. 从笔记与搜索两个入口打开同一笔记，确认共享编辑；在另一客户端修改正文后，检查本机保存冲突及另存副本。
5. 用复杂 HTML 笔记测试「编辑 HTML 源码」，仅修改标题后确认正文没有改变。
6. 打开今日日记两次，确认复用服务端日期笔记；快速记录后检查它是日期笔记的子笔记。
7. 搜索中文、空格、`#标签`、`&`、`+`，快速更换关键词和搜索目录，检查结果匹配最新输入。
8. AI 生成、停止、重试、切换到后台，再恢复；测试上下文开关、保存目录、保存到今天、重复保存及服务端冲突/删除后另存副本。
9. 在 Releases 下载 IPA 和校验和，完成自己的签名后，检查小屏幕、深色模式、键盘和动态字体体验。

## 项目结构

```text
TriliumPocket/
  App/        应用入口、连接状态和共享编辑模型
  Core/       ETAPI、AI SSE、数据模型、Keychain 和本机存储
  Features/   目录、编辑器、日记、搜索、AI 和设置
  Resources/  Info.plist 和图标
TriliumPocket.xcodeproj/   原生工程和共享 scheme
scripts/                  无依赖工程生成及静态检查工具
tests/TriliumPocketTests/  接口契约、编辑状态和 SSE 测试
.github/workflows/        CI 和 Release 工作流
```

新增 Swift 源文件后，使用已存在的 Python 运行 `scripts/generate_project.py` 可更新工程引用；Actions 会自动执行生成器。应用只依赖 Apple 系统框架。
